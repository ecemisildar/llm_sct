SCT RULES

1. Use only events declared by the supplied fixed plants, with exact spelling and case. Select only task-level events relevant to the user input.
2. Every event used by a generated specification must exist in at least one supplied fixed plant. Do not create a plant to introduce an event.
3. Include every transition event in that specification's `events` field. Keep the local alphabet minimal and relevant to the control objective.
4. The converter completes each generated specification with the selected plants' event alphabet. A globally unused controllable event is declared without transitions and therefore disabled. A controllable event selected by another generated specification is completed with self-loops so independent specifications do not disable it.
5. Explicitly write every uncontrollable transition that changes specification state. Missing uncontrollable transitions are completed as self-loops, so omit inert uncontrollable self-loops.
6. Never omit a required state-changing observation. In an ordered target phase, explicitly handle the requested target's reached observation from both search and approach states; it must not self-loop.
7. Make every automaton deterministic: each `(state, event)` pair has at most one target.
8. Add a controllable transition only where that request is semantically valid. A state may enable zero, one, or multiple controllable events.
9. Treat `only`, `never`, `must not`, and equivalent objective language as event-exclusion requirements.
10. Every transition source and target must belong to `states`, and every listed state must be reachable from `initial_state`.
11. Use short, unique names containing only letters, numbers, and underscores.
12. Mark only acceptable completed conditions, stable checkpoints, or legitimately repeatable mission conditions. Do not mark transient states with outstanding obligations. Always include `marked_states`, using an empty array only when no marked condition exists.
13. Generate a nonblocking specification whenever the objective permits it: every reachable state must be marked or have a path to a marked state.
14. Do not add behavior unrelated to the objective. Use color, communication, reception, skip, or obstacle events only when relevant.
15. Return valid JSON containing only the required automata, explanation, and transition-string representation.
